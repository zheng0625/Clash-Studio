## 工程优化建议与执行顺序

1. 本批优先完成 FE-01 至 FE-06，提供可重复运行的前端回归命令。
2. 提取设置写入、规则合成等有明确边界的逻辑，逐步减轻约 74.5 KB 的 `Client.vue`；后续再拆运行控制、轮询和导航，配合行为回归。
3. 整理 14 份全局 CSS 的职责与覆盖顺序。审计时生产主样式约 196.74 kB（gzip 32.34 kB）。按页面分离样式前需覆盖桌面/Android、深浅主题和照片背景的视觉验收，避免破坏现有层叠。
4. 将现有独立验收脚本归入统一入口，并覆盖保存失败、慢响应、跨表单保存及大量规则。浏览器脚本与原生网络接管验收分别记录。

样式全面归并、主组件整体拆分属于后续阶段，本报告不将其记为已完成。

## 验证记录

初始审计：`vue-tsc --noEmit` 和 Vite 生产构建通过。使用原组件脚本、Vue 响应式系统和模拟接口复现 FE-01 至 FE-05；规则计算执行原逻辑抽样。

2026-10-28 首批实施结果：

- `pnpm --dir frontend test`：10 项通过。覆盖发布快照与晚到编辑、保存失败保留草稿、多表单未保存状态、端口保留、并发设置合并与失败后队列恢复、原生字符串错误与结构化 HTTP 错误、本地文件选择取消/失败、规则语义、分页和大规则集性能。
- `pnpm --dir frontend exec vue-tsc --noEmit`：通过。
- Vite 生产构建：通过，输出到系统临时目录以保留现有 `frontend/dist`。仍有原有 Tauri core 同时被静态及动态导入的分包提示，不影响构建。
- `scripts/verify-frontend-save-audit.cjs`：Chrome 无头浏览器通过。覆盖目标本地文件编辑、250 项节点/规则的 100 条分页及原始优先级、订阅信息和共享设置离开保护、保存期间 inert 锁定、发布后的内容、网络草稿保存不回滚新端口；无页面异常。
- 已有 `scripts/verify-audit-ui.cjs`：通过页面轮询、连接分页、详情、暂停恢复、筛选保留、关闭连接验证。
- 已有 `scripts/verify-backend-bridge.cjs`：通过桌面任务轮询、稳定失败码及 Android 直接生命周期响应的浏览器模拟验证。
- 更新后的 10,000 条完整排序规则，在隔离执行实际 Vue computed 声明的单次测试中为 **10.19 ms**；初审同类测试为 831.18 ms。纯辅助函数抽样约 6 ms。均非整页或真机性能，不作为固定性能保证。

浏览器验收使用 Vite 的 `ui-preview.html`、受控模拟接口和独立浏览器上下文，未调用真实后端或启动代理。未执行真实 Android 设备、Tauri 桌面窗口或 VPN 联网验收。

可重复执行入口：

```powershell
# 逻辑回归及生产构建
pnpm --dir frontend check

# 浏览器回归：先在另一终端启动独立预览服务器
pnpm --dir frontend exec vite --host 127.0.0.1 --port 5196 --strictPort
pnpm --dir frontend test:browser
```

浏览器脚本需要可解析的 `playwright` 包与 Chrome；可通过 `UI_PREVIEW_URL`、`BROWSER_CHANNEL` 指定预览地址和浏览器通道。本次使用本机 Codex 运行时已有的 Playwright，通过 `NODE_PATH` 提供依赖，没有新增或下载依赖。

本批新增 `client-settings.ts` 和 `config-rules.ts`，先提取明确的写入及计算边界；全面拆分 `Client.vue` 和归并全局样式仍列入后续阶段。

设置保存队列用于协调同一前端页面内的写入；跨进程或其他客户端并发写入仍需服务端版本校验，不能将前端队列视作全局事务。
