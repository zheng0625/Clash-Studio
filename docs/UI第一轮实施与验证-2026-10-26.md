# Clash Studio UI 第一轮实施与验证

日期：2026-10-26。依据《UI修改建议-2026-10-26.md》的第一阶段开展；建议稿是设计参考，本记录说明实际实施范围，不表示全部建议已完成。

## 已实施

- UI-01：统一显示运行方案、当前所选／编辑方案、未保存、待应用、应用中、失败与已应用状态。无变更时保留次级“重新应用”，启动和应用失败可重试；成功提示要求后端返回匹配的运行配置，刷新失败不提示应用成功。
- UI-01／UI-07 的部分内容：网络设置增加固定保存条、未保存离页保护；“应用行为”独立展示并注明立即保存。DNS 与局域网修改失败后保留输入，后台端口刷新不覆盖未保存表单。
- UI-05／UI-09：首页先显示运行方案、方案选择、接管方式、分流模式和启动／断开操作；订阅和模块数量改为紧凑入口；实时速率和出口信息提前，详细流量趋势折叠。内核运行状态与出口检测仍分别展示。
- UI-02／UI-06／UI-10：桌面节点名 14px，手机 15px，辅助信息 12px；长名称允许换行。增加中英文节点搜索、展示层延迟排序、已测可用筛选、清除筛选、定位当前节点和桌面卡片／紧凑视图。手机默认紧凑行。排序不修改配置成员顺序，也不改变自动策略组的选择权限。
- UI-12：手机浮动按钮增加“测速”文字；展开工具后可选择 Cloudflare／Google 地址、全部测速与取消，原有整组／单节点测速保留。未测速、等待、测速中、取消、请求失败、后端报告的超时／不可达分别显示；后端未区分超时与不可达，UI 不推断这两种原因。
- 新增文案提供英文翻译；沿用现有主题、配色和 Android 导航方案。

## 实际验证

使用本机 Chrome 无头浏览器、项目隔离 `ui-preview.html` 示例和测试中注入的模拟响应，未提交真实网络配置或启动 VPN。

| 检查 | 结果与范围 |
| --- | --- |
| 类型检查、生产构建 | `pnpm --dir clashstudio/frontend build` 通过；Vite 仍报告 Tauri core 同时静态／动态导入的分块提示，不影响构建 |
| 桌面 1280 × 720 | 主操作位于约 y=571–609，避开底部 Dock；可同时看到运行方案、接管／分流模式、速率及出口摘要 |
| 手机 393 × 852 | 首页主操作可见；代理首个节点顶端约 y=424，前三个完整节点行在 y=660 前结束；节点名字号 15px |
| 手机 360／393／430px | 检查页面横向溢出；393px 另检查英文布局 |
| 36 节点模拟列表 | 中文搜索、英文大小写搜索、空结果清除、延迟排序、已测可用过滤、当前节点定位、紧凑视图通过 |
| 应用失败 | 模拟后端拒绝，显示失败与重试，不显示应用成功 |
| 网络设置 | 修改后显示固定保存条；离页取消保留开关；模拟保存失败后保留未保存状态 |
| 手机测速 | 工具可展开，Google 检测地址可选择 |
| 主题 | 检查浅色、深色和合成明暗背景；背景检查使用测试图，不是真实照片验收 |
| 页面脚本异常 | 上述交互未出现 pageerror |

验证脚本和截图保存在工作区 `D:/codex/clash开发/artifacts/ui-first-pass/`，脚本为 `check.cjs`。需要本机 Playwright、Chrome，以及 5187 端口运行的前端开发预览；脚本只操作隔离预览。
