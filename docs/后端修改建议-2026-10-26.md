# Clash Studio 后端修改建议

审查日期：2026-10-26。范围：当前工作区 `clashstudio` 的 Python 服务、配置引擎、Rust 桌面请求转发和 Android Java 原生服务。

配套文档：[UI 修改建议](/D:/codex/clash开发/clashstudio/docs/UI修改建议-2026-10-26.md)。

本文保留修改前的审查快照。2026-10-26 已完成对应代码实施和主机回归，详细完成范围、性能结果及待设备验收项见 [后端修改实施与验证](后端修改实施与验证-2026-10-26.md)。下文的原问题与旧性能数字描述审查时状态，不代表修改后的运行表现。

## 1. 修改目标与优先级

优先保证配置、内核和界面状态一致，然后减少慢任务阻塞与重复计算。

| 级别 | 含义 | 建议范围 |
| --- | --- | --- |
| P0 | 优先修复可能导致实际网络状态与返回结果不一致的路径 | 完整回滚、Android 启动取消 |
| P1 | 改善高频操作响应与状态准确性 | 任务隔离、配置缓存、统一采样、出口缓存失效 |
| P2 | 降低数据增长后的成本，改善维护和排障 | Android 存储拆分、规则算法、接口契约与诊断 |

现有应保留的机制：订阅与工作空间版本冲突检查、SQLite WAL、设置和工作空间的临时文件替换、Android 原子存储、测速并发限制、系统代理所有权检查、部分应用失败回滚、YAML 大小和引用展开限制、已有平台与生命周期测试。

## 2. P0：补齐配置应用的完整回滚

**当前问题（隔离验证）**

普通热加载中，内核接受新配置后还要恢复策略组选择、写入 `active.yaml`、更新 `active` 等运行记录。恢复节点或落盘失败时，异常处理没有覆盖整个提交过程，可能留下“内核使用新配置、运行记录仍是旧版本”的状态。当前针对热加载请求和 TUN 检查的回滚应继续保留，并扩展覆盖后续步骤。

代码位置：[runtime.py:328](/D:/codex/clash开发/clashstudio/server/runtime.py:328)、[runtime.py:374](/D:/codex/clash开发/clashstudio/server/runtime.py:374)。

**修改建议**

1. 明确应用阶段：准备、校验、加载、恢复节点、持久化、提交运行状态。
2. 提交前保存旧配置、节点选择、运行元数据及代理接管状态快照。
3. 将恢复节点与落盘纳入统一失败处理；恢复后核验实际状态。无法恢复时停止内核并执行现有代理恢复流程，返回明确的恢复结果。
4. `active.yaml` 采用临时文件写入和原子替换，避免失败时破坏唯一回退文件。
5. 区分首次启动、普通热加载、TUN 迁移三类失败后的收尾行为，避免共用分支遗漏资源清理。

**验收标准**

- 注入节点恢复失败、写入失败、替换失败、回滚失败，分别核对返回结果、实际加载配置、元数据和系统代理状态。
- 返回“已恢复旧配置”前必须完成核验；无法确认时明确返回失败状态。
- 首次启动失败后不遗留未登记的内核进程或监听端口。

## 3. P0：Android 启动超时必须取消后续接管

**当前问题（代码路径确认，待 Android 故障注入）**

启动等待上限为 90 秒，超时会取消请求结果；取消检查位于启动开始及 `quickSetup` 后。后续逐组恢复选择、原生操作与建立 VPN 隧道前，没有再次核对取消。存在调用方已收到超时，后台仍继续建立 VPN 的路径风险。

代码位置：[CoreRuntime.java:83](/D:/codex/clash开发/clashstudio/android/app/src/main/java/studio/clash/android/CoreRuntime.java:83)、[CoreRuntime.java:139](/D:/codex/clash开发/clashstudio/android/app/src/main/java/studio/clash/android/CoreRuntime.java:139)。

**修改建议**

- 为每次生命周期操作设置编号、截止时间和取消标记；新操作与旧操作的返回结果严格隔离。
- 在每个耗时步骤前后、建立隧道前、发布运行状态前检查取消及操作编号。
- 原生接口允许取消时主动取消；无法取消时，在结果返回后丢弃过期结果并执行资源清理。
- 停止请求能够撤销正在启动的操作；保持生命周期操作串行执行，避免并发创建和销毁同一 VPN。
- 超时后的清理结束前，不把生命周期状态提前视为完全空闲。

**验收标准**

- 人为延迟 `quickSetup`、恢复节点或原生回调，确保超时后不会晚建立隧道或发布“运行中”。
- 连续启动、停止、重新启动时，只允许最新有效操作提交状态。
- 验证系统撤销 VPN 授权、Activity 销毁、前后台切换时的资源释放。

## 4. P1：隔离慢任务，缩短状态锁占用

**当前问题（代码确认，影响程度需压测）**

桌面应用配置在 `runtime.lock` 内执行校验、请求和等待，其中配置校验超时可达 90 秒；查询状态和停止也依赖同一把锁。Android 常规消息桥请求使用 2 个工作线程和长度为 16 的有界队列，下载、测速、启动的同步等待可能占满工作线程，导致状态查询和停止请求排队。

代码位置：[runtime.py:266](/D:/codex/clash开发/clashstudio/server/runtime.py:266)、[MainActivity.java:47](/D:/codex/clash开发/clashstudio/android/app/src/main/java/studio/clash/android/MainActivity.java:47)、[MainActivity.java:153](/D:/codex/clash开发/clashstudio/android/app/src/main/java/studio/clash/android/MainActivity.java:153)。

**修改建议**

- 将下载、测速与生命周期操作分配到职责明确的有界执行队列，设置排队上限与取消行为。
- 状态查询读取带采样时间的快照；状态锁只保护读取快照和提交状态等短操作。
- 桌面耗时准备尽量移出状态锁；提交前重新检查配置版本和内核会话，继续串行化有副作用的生命周期操作。
- 为长任务提供操作编号与进度，让接口快速返回任务已受理，而不是一直占用请求线程等待。
- 控制入口要能及时登记停止或取消意图，实际资源变更仍交由生命周期执行器统一处理。

FastAPI 同步端点会在线程池运行，优化重点是线程占用、排队和锁等待；可参考 [Starlette 线程池说明](https://starlette.dev/threadpool/)。

**验收标准**

- 在慢订阅下载、批量测速和配置应用同时发生时，记录状态查询与停止请求的排队时间。
- 记录操作队列长度、状态锁等待时间及接口 P50/P95，建立修改前后可比较的基线。
- 达到队列上限时返回明确的忙碌状态，取消后不继续启动排队中的过期任务。

## 5. P1：缓存配置合成结果，合并同版本计算

**当前问题（代码确认与合成测试）**

单节点测速携带订阅 ID 时，会经过 `profile_config → compose`，重新解析、复制并序列化整份配置；这部分发生在 `DelayMonitor` 的测速并发限制之前。订阅摘要、详情也存在重复解析。

代码位置：[api.py:159](/D:/codex/clash开发/clashstudio/server/api.py:159)、[api.py:381](/D:/codex/clash开发/clashstudio/server/api.py:381)、[modules.py:83](/D:/codex/clash开发/clashstudio/server/modules.py:83)、[vendor/app/main.py:186](/D:/codex/clash开发/clashstudio/vendor/app/main.py:186)。

本机生成虚构节点和规则、调用当前 `compose`，每种规模执行 3 次：

| 节点数 | 规则数 | YAML 大小 | 单次耗时中位数 |
| --- | --- | --- | --- |
| 50 | 501 | 27.6 KiB | 124.0 ms |
| 200 | 3001 | 155.6 KiB | 599.0 ms |

上述结果仅包含配置合成，不含网络测速；样本数量有限，不能用于推断所有机器上的性能或优化收益。

**修改建议**

- 以订阅 ID、订阅版本、工作空间版本构成缓存键；若缓存包含设置覆写后的最终配置，再加入设置版本。
- 对缓存未命中的同版本并发请求只执行一次合成，其余请求共享结果。
- 缓存对象按不可变数据处理；需要修改时复制，避免运行配置污染缓存。
- 对只需要节点目录的接口跳过 YAML 输出；订阅摘要计数在发布或刷新时计算。
- 设置缓存容量和失效策略，只在成功提交更新后使相关缓存失效。

**验收标准**

- 同一配置版本连续或并发测速时，仅首次请求进行完整合成。
- 更新订阅、工作空间或影响最终配置的设置后，相关缓存立即失效。
- 缓存命中前后配置输出、校验结果与节点目录一致。
- 使用相同合成数据记录调用次数、耗时和峰值内存，避免只测试小配置。

## 6. P1：统一运行数据采样，复用内核 HTTP 客户端

**当前问题（代码确认，收益需测量）**

`traffic()` 通过完整 `/connections` 响应提取累计流量与连接数量；连接页又独立读取完整连接列表。`Runtime.request()` 每次创建并关闭一个 HTTPX 客户端，无法跨调用复用连接池。

代码位置：[runtime.py:79](/D:/codex/clash开发/clashstudio/server/runtime.py:79)、[runtime.py:159](/D:/codex/clash开发/clashstudio/server/runtime.py:159)、[api.py:428](/D:/codex/clash开发/clashstudio/server/api.py:428)、[Client.vue:166](/D:/codex/clash开发/clashstudio/frontend/src/Client.vue:166)。

**修改建议**

- 按内核会话复用 HTTP 客户端，保留 `trust_env=False`，明确连接数与不同操作的超时。
- 客户端使用稳定的会话地址和认证信息；重启内核后创建新会话，退出时关闭并处理在途请求。
- 合并相近时间的连接采样，向流量统计和连接视图提供同一快照；连接详情按页面需要获取。
- 高频状态与低频诊断分开采样，进程冲突扫描等操作不必随每次状态读取执行。
- 快照包含会话、采样时间与错误状态，过期数据不能伪装成刚采集的实时数据。

参考：[HTTPX 客户端与连接池](https://www.python-httpx.org/advanced/clients/)。

**验收标准**

- 相同时间窗口内的多个界面请求不会重复拉取同一完整连接列表。
- 测试内核重启、请求超时和退出期间，不返回旧会话数据、不泄漏客户端连接。
- 对较多连接的合成响应比较请求次数、响应体积、解析耗时与内存。

## 7. P1：补齐出口缓存失效与旧结果丢弃

**当前问题（隔离验证）**

公网 IP 缓存键仅包含检测路径、进程 PID 和配置哈希，节点选择或规则／全局／直连模式变化未进入缓存键。代码还允许“强制刷新”复用最近 5 秒的缓存。

隔离测试中改变分流模式后调用 `lookup(..., refresh=True)`，仍命中原缓存，没有发出新网络请求。该验证使用虚构 IP，未查询真实出口。

代码位置：[network.py:43](/D:/codex/clash开发/clashstudio/server/network.py:43)、[NetworkDashboard.vue:47](/D:/codex/clash开发/clashstudio/frontend/src/NetworkDashboard.vue:47)。

**修改建议**

- 引入出口变更版本，在手动节点切换、模式变更与运行配置更新时递增。
- 缓存键与检测请求记录该版本；返回结果前再次核对，丢弃过期检测结果。
- 自动策略组变化需要监听或核对实际选择，不能只依赖手动操作失效。
- 出口变化后的显式检测不得复用旧出口缓存；同一出口版本的重复点击仍可合并。
- 前端在出口变化后显示“待重新检测”，避免长期保留旧 IP 造成误解。

**验收标准**

- 切换节点、模式后立即检测，不能返回旧出口版本的缓存。
- 检测过程中切换出口，旧请求结果不会覆盖新状态。
- 自动组切换、内核重启和检测服务不可用时，分别验证缓存行为。

## 8. P2：拆分 Android 高频状态存储

**当前问题（代码确认，规模影响需测量）**

每次保存节点选择都会复制整个状态，并序列化、同步写盘包含订阅和历史的完整 JSON。原子替换与同步落盘已实现，建议保留其一致性保证，减少单次写入范围。

代码位置：[ProfileStore.java:32](/D:/codex/clash开发/clashstudio/android/app/src/main/java/studio/clash/android/ProfileStore.java:32)、[ProfileStore.java:175](/D:/codex/clash开发/clashstudio/android/app/src/main/java/studio/clash/android/ProfileStore.java:175)。

**修改建议**

- 先将节点选择、设置与订阅正文及历史分开持久化。
- 为拆分后的文件或表定义迁移版本、失败恢复及关联清理规则。
- 按规模评估 SQLite；迁移时保留旧数据备份，验证完成后再提交新版本。
- 连续切换同一组可合并中间写入，但必须明确确认成功与可靠落盘的关系，不能静默丢失最终选择。

**验收标准**

- 切换单个节点的写入量不再随所有订阅及历史总量线性增长。
- 注入磁盘满、写入失败和迁移中断，旧数据仍可恢复。
- 删除订阅、恢复历史后，不残留错误的节点选择关联。

## 9. P2：优化规则算法并统一接口契约

**当前问题（代码确认）**

规则重排通过列表成员判断筛选顺序和剩余规则，规则数量和自定义顺序都很大时会产生平方级扫描。严格出口检查对共享子图也存在重复遍历机会。两端实现相近的业务接口，适合用共用数据集约束行为。

代码位置：[engine.py:194](/D:/codex/clash开发/clashstudio/vendor/app/engine.py:194)、[modules.py:93](/D:/codex/clash开发/clashstudio/server/modules.py:93)、[NativeApi.java:39](/D:/codex/clash开发/clashstudio/android/app/src/main/java/studio/clash/android/NativeApi.java:39)。

**修改建议**

- 使用集合做成员判断、列表保存顺序；维持去重与最终兜底规则的位置语义。
- 严格出口检查对已完成检查的子图缓存结果，同时保留循环检测，避免缓存掩盖循环路径。
- 建立桌面和 Android 共用的有效配置、无效配置、版本冲突与输出预期数据集。
- 定义稳定错误码、用户提示、可重试标志和操作编号，界面不依赖错误文案判断状态。
- 增加按操作编号关联的结构化诊断信息，记录阶段、耗时、版本、回滚结果；不记录完整订阅 URL、密码或控制密钥。

**验收标准**

- 大规则集的重排结果与现有语义一致，且不再执行嵌套线性成员扫描。
- 循环组、共享子图、动态 Provider 和直连出口仍得到预期检查结果。
- 两端接口公共能力通过同一组数据验证，平台差异通过能力字段明确表达。
