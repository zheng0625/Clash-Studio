### 超时与取消

未缩短生产代码的 90 秒启动上限。验收在 quickSetup 完成后的 Java 续执行边界注入 96 秒延迟，启动请求约 89.65 秒后返回 504；当时仍保持取消与清理占用，新的启动返回 409。旧步骤返回后完成清理，没有继续建立 VPN；随后三轮启动和停止均正常。

原生回调场景将 getProxies 回调交付延迟 40 秒，超过原生操作的 30 秒等待上限。请求返回 504，等待迟到回调交付后再次确认没有运行中的 VPN，也没有遗留混合代理监听。

故障注入位于 Java / 原生交互边界，不修改 Mihomo 二进制。这验证了过期结果不能继续提交，并不声称覆盖 Go 内部所有异常。

### 真机响应时间

| 建隧道前故意阻塞 | 8.29 ms | 8.70 ms | 12 |
| 恢复节点后故意阻塞 | 7.01 ms | 10.57 ms | 12 |
| 慢下载、饱和测速、启动并发 | 10.54 ms | 12.10 ms | 20 |

并发场景下停止意图约 **20.53 ms** 被登记。由于专门注入了不可抢占的 6.5 秒等待，资源清理约 5.95 秒后完成；该数字与“停止意图登记时间”分开记录，没有把清理描述为瞬时完成。

并发场景最终得到 12 个 409 和 1 个 429，两个慢下载按预期返回 502。测试服务器只接受 TLS 连接而不完成握手，下载失败是故障注入的预期结果。服务器只收到这两个下载连接，没有收到过期测速引发的新连接。

### 系统与 Activity 生命周期

后台切换和 Activity 销毁重建后，已建立的 VPN 会话保持不变。启动过程中销毁 Activity 会取消启动，清理后能够再次连接。

系统撤销授权使用 Android VPN 设置中的“取消保存 VPN”，确认实际触发撤销并释放资源。单独修改 AppOps 在该设备上不会撤销已经建立的 VPN，因此没有把 AppOps 变更当作这一项验收的替代。还实际点击系统 VPN 授权弹窗的“确定”，确认批准回调能通过生命周期队列启动 VPN。

## 真机验收发现并修复的问题

1. **清理回调误取消请求**：`shutdown()` 释放服务后，稍后抵达的 `onDestroy → revoked` 仍会取消当前请求，把原生超时的 504 改写为 409，也可能影响下一次启动。现在先核对服务归属，已释放的旧服务回调不再取消操作。
2. **桥接队列中过期测速继续运行**：停止只能清除已经进入内核生命周期队列的任务；消息桥中排队的 8 个测速仍会在停止后启动测试内核。现在启动、测速和探针准备统一核对停止版本；系统授权批准回调也使用同一生命周期队列和版本检查。

两项修复均已通过最终 APK 的设备回归；第二项修复前可复现 8 个停止后继续执行的 200，修复后变为取消响应，并消除了对应的黑洞连接。

## 复现

```text
gradlew.bat --offline --no-daemon -PacceptanceBuild=true -PincludeVpnProbe=true :app:assembleDebug :vpn-probe:assembleDebug
```

安装后仅对验收包授予通知和 VPN 权限（实际系统弹窗或授权测试设备的 ADB AppOps），不要对原应用清除数据或变更授权。配置 `ADB`、`ANDROID_SERIAL`、`ANDROID_PACKAGE=studio.clash.android.validation.acceptance` 后依次运行：

```text
node clashstudio/scripts/verify-android-vpn.cjs
node clashstudio/scripts/verify-android-lifecycle.cjs
node clashstudio/scripts/verify-android-concurrency.cjs
```

生命周期完整脚本包含真实的 90 秒等待。仅补跑 Activity / 授权场景时可设置 `ANDROID_ACTIVITY_ONLY=1`。当前系统设置控件按该设备的中文界面识别，并校验验收应用名称和设置按钮所在行；无法确认归属就停止，防止操作其他 VPN。作用域检查可运行 `node clashstudio/scripts/verify-android-ui-scope.cjs`。其他 ROM 或语言需要重新核对控件。脚本要求测试前没有正在运行的 VPN；测试后仍需清理临时 APK。最终构建记录位于 `artifacts/android-device-final-build.log`。
