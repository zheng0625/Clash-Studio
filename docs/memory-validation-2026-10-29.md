## 2. 结果

| 用例 | 结果 | 说明 |
| --- | --- | --- |
| 代理组总渲染预算 | 16 组、**300** 张 `.proxy-node-card` | 每组显示“第 1 / 6 页 · 每页最多 19 项”；不再出现 16 组 ×20=320 |
| 折叠卸载 | 全部折叠 **0** 张；展开 1 组 **100** 张；全部展开 **300** 张 | 真实 DOM 数量，证明 `v-if` 卸载与预算重新分配 |
| 节点搜索覆盖完整集合 | 搜索“节点 99”得到 **16** 张卡片，全部为节点 99 | 节点 99 不在首屏，说明搜索基于完整逻辑集合而非当前页 |

| 暂停/恢复 | 暂停显示“已暂停显示”；恢复显示“每 3 秒刷新” | 暂停快照保留，恢复后列表刷新 |

| 内存角色拆分 | 明细显示桌面宿主 32 MB、WebView 44 MB、本地服务 42 MB、主内核 32 MB；“私有提交合计 120 MB” | 测速内核与其他进程为 0 时不显示 |

## 3. 复现方式

手动（本次实际执行）：

1. `pnpm --dir frontend dev --port 5178 --strictPort`
2. 打开 `ui-memory.html`
3. 通过导航、折叠、搜索、暂停/恢复与 `memory-probe` DOM 计数观察上述值。`window.__memoryProbe` 的页面全局在 CUA 隔离世界不可见，因此测试入口同时把同一份计数写入隐藏的 `#memory-probe` 节点。

自动化脚本（需要 Playwright；本机未安装，本轮未执行该脚本）：

```powershell
pnpm --dir frontend dev --port 5178 --strictPort
node scripts/verify-memory-ui.cjs
```

脚本覆盖同一组断言，失败时以非零退出码结束，结果写入 `artifacts/memory/browser-validation-auto.json`。

## 5. 限制

- 页面来自 Vite 开发入口，不是 Windows Release 包；WebView2 版本、GPU/合成层与真实进程树不同。
- 没有 retained heap、detached DOM 或监听器快照；“300 张卡片”只证明当前 DOM 数量，不证明长期堆收敛。
- `document.hidden` 由测试入口驱动，不等同于原生窗口隐藏或 WebView2 挂起。
- 5,000 条连接，不是 20,000；2,000 节点/30,000 规则的实际大配置未在本轮浏览器中加载。
- 合成数据不经过真实内核、TUN 或系统代理，不能替代联网验收。

结论：浏览器轮次证明 R2（严格 300 上限）、M02（分级与隐藏停止）、M03（离页停止连接请求）和 M01 角色显示在真实 DOM 中生效；性能总量与平台正确性仍需 Release S0–S7 与实机回归。
