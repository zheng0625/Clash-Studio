# Clash Studio UI 优化操作方案

日期：2026 年 10 月 28 日  
依据：桌面文件《UI优化.docx》的八项提案、导入订阅截图，以及当前 `clashstudio` 工作区代码。  
用途：用于设计确认、开发拆单和逐项验收。下文均为待执行任务，不表示客户端已经完成改造。

本轮围绕三个结果展开：主要文字清晰可读，卡片尺寸与内容匹配，概览能够直接选择方案、策略组和节点。先统一字体与间距，再精简概览，最后接入选择联动并验证状态一致性。

## 一 实施范围与执行原则

以 Windows 和 Linux 桌面客户端为主。共享组件同时检查 Android，保持手机的单列布局、触控尺寸及 VPN 能力判断。文档中的桌面布局不直接套用到手机。

保留现有主题、背景设置和导航体系。本轮将“AI 感强”转为可检查的表现：减少大面积装饰留白、英文装饰眉题、宣传式标题、重复说明和重复状态；使用直接描述用途的名称。业务逻辑继续复用已有导入、方案选择、节点选择、应用和停止流程。

“删除提示”落实为移除各页上方的重复常驻信息，并将必要反馈放在对应操作旁。未保存修改、应用失败、权限不足和数据读取失败仍需能够被用户感知。

## 三 先确定两个数据约定

### D01 DNS 显示配置来源

当前 `NetworkDashboard.vue` 的 `Lookup` 类型以及 `/api/client/network/ip` 返回的是公网 IP 与归属地信息，不包含实际 DNS 出口检测数据。不能把 IP 检测服务地址、系统代理地址或预设 DNS 写成“检测到的 DNS”。

本方案默认展示“DNS 配置”，用于说明当前配置使用的解析器，不宣称已完成 DNS 泄漏检测：

1. 运行时读取内核实际生效配置中的 DNS 摘要；停止时读取所选方案合成后的 DNS 摘要。
2. 优先使用有效的 `nameserver` 信息；多个解析器默认显示第一项及“另 N 项”，展开可看完整列表。开启 DNS 防泄漏时展示其实际生成的配置结果。
3. 字段值用“运行配置”或“所选方案”短标签标明来源；不能用当前编辑值代替尚未重新应用的运行值。
4. 没有可读取的有效配置时显示“未获取”，不填示例地址。自定义解析器 URL 如含凭据或查询参数，界面摘要应隐藏这些部分。
5. 复用现有设置与合成配置能力；若前端拿不到有效运行摘要，增加只读摘要接口。不要为了展示 DNS 将完整运行 YAML 暴露给页面。

建议摘要字段为 `source`、`profile_id`、`config_hash`、`nameservers`、`status`。该结构是拟新增契约，实施时先核对现有配置读取接口。

如果后续明确要求“检测真实 DNS 出口”，另拆后端检测任务，定义检测方法、超时、刷新和失败语义；本轮不把配置展示当作检测结果交付。

### D02 所选方案与运行方案分别处理

当前 `selected` 表示工作区所选订阅，`runtime.active` 表示正在运行的配置。两者可能不同，修订号也可能不同。新增选择面板统一复用 `/api/client/proxy-catalog` 返回的目录与 `live` 标志，不能仅凭订阅 ID 相同就判断已生效。

1. 选择方案调用 `choose()`，更新所选方案及其目录；不自动重启内核。
2. 策略组下拉来自该目录的组成员。默认恢复本次会话选中的组；失效时回退到第一个可选组，必要时再回退到自动组。
3. 手动组可以选择成员；自动组仅显示当前结果及“自动选择”，禁用手动成员选择。
4. 节点选择复用 `selectProxy()` 和 `/api/client/proxy-selection`。`live=true` 时作用于当前内核；否则保存为该方案下次应用使用的选择。
5. 运行另一方案或配置修订不一致时，在选择卡片内显示“待应用”，启动按钮使用“应用变更”；停止状态下在卡片内显示“下次启动使用”。
6. 切换方案立即清空旧的组和节点选项。请求带方案及修订信息，迟到结果不能覆盖新方案；失败恢复最后确认的选择，并显示可重试反馈。
7. 组成员如果仍是一个策略组，应标为“策略组”，显示链路摘要；不能把它伪装成最终节点，也不直接将嵌套叶节点提交给上层组。
8. Provider 尚未加载时显示“节点未加载”及加载入口，不自动启动主内核；直连模式下将节点选择禁用并标注“不使用代理节点”。全局模式使用实际可用的 GLOBAL 组；离线目录缺少 GLOBAL 时提供前往代理页的入口。

现有目录主要在代理页加载。新增概览选择面板后，必须同步调整 `choose()`、`pollOnce()` 与 `loadCatalog()` 的调用条件，并继续使用请求合并与代次校验；其他页面不因此开始轮询完整节点目录。

## 四 统一视觉参数

以下为首轮实施值，不是现有界面的测量结果。使用浏览器 CSS 像素；先在 1280 × 800 窗口验证，再根据长名称和英文文本微调。

| 元素 | 目标值 | 执行要求 |
| --- | --- | --- |
| 正文、表单和普通按钮 | 15 px | 不通过缩小正文解决排版问题 |
| 次要信息、字段标签 | 13 px | 必要说明不低于此值 |
| 页面标题 | 24–26 px | 去掉装饰性句点与多余眉题 |
| 卡片标题、策略组名称 | 17–18 px | 层级清晰，字重 600 |
| 节点名称 | 15–16 px | 默认两行，完整名称可查看 |
| IP 主值 | 20–22 px | IPv6 可换行，复制按钮不被挤出 |
| 卡片内边距 | 16 px；窄屏 12 px | 移除无内容支撑的最小高度 |
| 卡片间距 | 12–16 px | 同组表单间距 8–12 px |
| 按钮、输入与选择控件高度 | 桌面至少 36 px | 手机主要触控区域至少 44 px |
| 圆角 | 卡片 12–16 px；控件 8–10 px | 同类控件一致 |
| 节点网格间距 | 8–10 px | 先调整列数再考虑截断 |

使用语义色区分正文、辅助文字、边界和焦点。导入方式弱化选中背景之后，仍通过字重和边框表达选中态，并保留键盘焦点。不能用统一低对比灰色掩盖选中、禁用和失败之间的差别。

实现时先记录关键元素的最终计算样式。当前 `main.ts` 连续加载多份历史样式，单改 `a11y-tokens.css` 不一定生效。将本轮有效规则收敛到 `ui-refinements.css` 等现有职责文件，限定组件类名，避免继续新增覆盖文件或全局 `small`、`button` 规则。

## 五 各页面的具体操作

### UI01 导入订阅弹窗

修改 `Client.vue` 中导入弹窗的 `.modal-tabs`，并添加专用类以避免影响其他标签页。

1. “订阅链接”和“YAML 文件”分别做成圆角按钮，文字 15 px、高度 36 px、间距 8 px。
2. 默认及选中背景均透明，去掉截图中的选中背景色与蓝色下划线。选中项使用加粗文字和清晰边框。
3. 使用可访问的按钮组选中语义，保留 Tab、Enter 和 Space 操作；如使用 tab 角色，则补齐方向键及面板关联。
4. 保持 URL、文件上传和粘贴 YAML 的原有校验。Android 的二维码入口采用同一套按钮样式。

验收：三种可用方式切换正确，选中项清楚，输入、文件上传、错误反馈、关闭时的未保存提醒均正常。

### UI02 与 UI08 全局字体与密度

1. 对概览、订阅卡片、代理页、设置分组、连接列表、模块编辑和工作台逐一登记字号、padding、gap、min-height。
2. 按上表统一正文和标题；卡片改为内容自然撑高，消除为了等高而产生的大块空白。空态只保留一句说明与一个主要入口。
3. 去掉概览中的 `ACTIVE WORKSPACE`、`YOUR ROUTING LOGIC` 等装饰性英文眉题；“分流，按你的意图”改为“已启用模块”，“你的网络出口”改为“网络出口”。功能性帮助只在需要时展开。
4. 订阅卡片优先呈现名称、用量、更新和主要操作，收拢重复说明。工作台与连接页保留现有分页能力，不因密度调整改成一次渲染全部记录。
5. 逐页检查照片背景、深色主题和英文模式下的可读性。

验收：主要操作文字达到目标字号，没有通过缩小文字或隐藏必要字段完成“紧凑化”；固定按钮和 Dock 不遮挡页面末尾内容。

### UI03 代理页

修改 `ProxyPanel.vue` 及其 `.proxy-group`、`.group-fold-toggle`、`.node-grid`、`.proxy-node-card`、`.node-choice` 样式。

1. 策略组名称改为 18 px，节点名称改为 15–16 px，类型和测速信息为 13 px。
2. 组卡片内边距 16 px；节点卡片内边距 10–12 px。删除无内容支撑的固定高度，保留当前节点选中标记。
3. 网格可从 `repeat(auto-fit, minmax(min(100%, 220px), 1fr))` 起步；按实际内容宽度自适应列数，组标题与操作区可以换行。
4. 节点名默认最多两行，可通过悬停或展开查看完整名称；测速按钮独立可点，延迟、失败和选中标记不互相挤压。
5. 同步处理卡片和紧凑视图；保留搜索、排序、折叠、定位当前、单节点及整组测速入口。

验收：长中文、英文、emoji 节点名均不覆盖测速控件；选择与测速正确；自动组不可手动选择；窄窗不出现页面级横向滚动。

### UI04 概览模块摘要

替换 `Client.vue` 的大尺寸 `.flow-card`，去掉流程示意空态和 `slice(0,4)` 截断逻辑。

1. 标题为“已启用模块”，内容仅来自当前所选方案的 `plan.module_ids`，按原有顺序展示。
2. 每项显示模块名、目标出口和严格模式标记，不展示条件列表。点击“管理”进入模块页。
3. 三项为一页，页数为 `max(1, ceil(N / 3))`，使用明确的上一页、下一页按钮；N≤3 不显示分页，无自动轮播。
4. 无模块时只显示“当前方案未启用模块”和管理入口；无方案时提示先导入。
5. 切换方案归第一页；删除或禁用模块后校正页码，避免停留在不存在的页面。
6. 本卡显示“所选方案”的模块配置。存在 `needsApply` 时，在选择卡片显示“待应用”，不得宣称这些模块已经在内核生效。若要求显示运行快照的模块，需要另补运行快照摘要。

验收：用 0、1、3、4、6、7 个模块验证分页；只显示已启用项，顺序与模块页一致；换方案后没有残留名称或空白末页。

### UI05 网络出口

修改 `NetworkDashboard.vue` 中 `.ip-card`，按 D01 接入 DNS 摘要。

1. 卡片标题下只保留 IP、DNS 配置、IP 位置三组字段。顶部保留刷新，IP 旁保留复制按钮。
2. 删除常驻检测路径、服务可达、服务商、ASN、检测时间、服务来源以及“遵循系统路由”“归属地仅供参考”等文字。
3. 卡片由内容自然撑高，减少标题与正文之间的间隔；DNS 过长可换行或展开，IPv6 不被截断。
4. 加载状态在对应字段中显示；查询失败在对应位置显示“未获取”和重试反馈，不能继续把旧 IP 当作当前结果。可查看错误详情，但不恢复大段常驻说明。
5. 保持现有 `route`、配置变化失效、请求代次判断和刷新行为；删除检测路径文案不改变实际请求路径。IP 刷新与 DNS 读取分别处理失败，互不覆盖。

验收：成功、部分成功、离线、快速切换配置、IPv6、多个 DNS 均有明确显示；IP 与位置来自同一结果；DNS 显示来源符合 D01；复制得到完整 IP。

### UI06 接管控制与快捷选择

将现有内核卡片整理为两个独立小区块。宽桌面建议两列，窄窗口按同一顺序纵向排列。

```text
接管控制                        方案选择
系统代理   TUN 模式              方案     [订阅 A       ▾]
规则   全局   直连                策略组   [手动选择     ▾]
[启动或应用变更] [停止]          节点     [节点名称     ▾]
更多设置                        需要时显示 待应用

实时速率                        网络出口
当前配置摘要                    已启用模块 每页三项
```

1. 删除“接管方式”文字、系统代理及 TUN 下方的小字、旧 `.home-plan-selection` 与 `.primary-strategy`。
2. 精简 `.kernel-summary` 的装饰图标及重复说明；接管按钮文字 15–16 px。保留系统不支持 TUN、权限申请等条件反馈。
3. 新建可独立验证的方案选择组件，提供方案、策略组、节点三个有标签的选择控件，执行 D02。
4. 将“当前配置方案”卡片里的第二个方案选择器删除，保留用量、更新时间、数量摘要与编辑入口，避免概览出现两个方案入口。
5. 保留现有规则、全局、直连的模式切换。它们与系统代理、TUN 表达不同的功能，不合并成一组。
6. 启动、停止和应用按钮继续调用原有生命周期入口，忙碌态禁用冲突操作；保留应用中取消或停止的现有处理能力。

验收：停止时能保存节点；运行当前方案时能切换手动节点；运行 A 时选择 B 不会把 B 的节点提交给 A；自动组、嵌套组、Provider、直连与全局模式行为符合 D02。

### UI07 删除顶部重复状态

1. 移除 `Client.vue` 页标题下 `.configuration-status` 整段，覆盖概览、订阅、模块、代理、连接、工作台和设置。
2. 移除概览内核卡片独立的“运行中／已停止”状态徽标，避免新增另一条常驻状态条。
3. 通过启动／停止／应用变更按钮本身表达可执行操作；必要的“待应用”“下次启动使用”在方案卡片内显示。
4. 运行配置与所选配置不同时，接管控制区显示实际运行方案的名称，防止用户将所选方案误认为已生效。这是差异出现时的局部说明。
5. 把未保存、读取失败和应用失败留在相关编辑区或操作区；点击操作产生的短时结果反馈继续保留。保留 `runtime`、`runtimeReady`、`needsApply`、`editorDirty` 等状态计算及按钮保护。

验收：切换每个页面不再出现顶部“内核已停止”“当前所选”和“当前方案已应用”横条；启动、停止、应用失败、未保存拦截仍正确工作。

## 七 分批执行与交付物

工作量为单名前端开发的初步估算；如 D01 需要后端摘要，额外预留 0.5–1 个工作日。下列均为开发估算，不是已经验证的工期承诺。

| 批次 | 执行动作 | 依赖 | 预计工作量 | 完成后必须交付 |
| --- | --- | --- | --- | --- |
| A | 确认 D01、D02，建立截图基线和计算样式记录 | 无 | 0.5 天 | DNS 口径、状态规则、前后对比基线 |
| B | 实施 UI01、UI02、UI03，收敛字体与间距 | A | 1 天 | 导入、订阅、代理的截图与差异 |

| D | 实施 UI06，再完成 UI07 | A、C | 1.5 天 | 三项选择联动、状态回归证据 |

合计约 5 个前端工作日，另计需要的后端摘要工作。设计与验收由产品确认视觉目标，前端负责页面和联动，后端负责可选摘要接口及数据来源，测试负责回归；单人项目可由同一人依次完成。

每批次单独保留差异和验收截图。先完成选择卡片中的局部反馈，再删全局状态横条。出现问题时可按批次回退，不涉及订阅数据迁移。
