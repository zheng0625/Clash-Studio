# Clash Studio 内存优化：Agent 任务与交付指南

日期：2026-10-29。配套：[内存优化方案](memory-optimization-plan-2026-10-29.md)。本文件供后续派发任务。2026-10-29 的第一、二批实现已在同一工作区执行，结果与未执行项见[实现报告](memory-optimization-implementation-2026-10-29.md)；下方任务卡仍可作为后续拆分与复核依据。

## 1. 所有 agent 的统一约束

工作目标是可验证地降低真实内存成本，同时维持功能。先读 `AGENTS.md`、配套方案、`BUILDING.md`、相关已有测试，再修改代码。

1. 方案对应的是当前脏工作区。集成人先保存包含相关未跟踪源码的可复现快照/检查点，记录父提交、文件清单及 SHA-256；不要直接从旧 HEAD 开工，不要把用户数据、凭据、工具链和二进制混入源码快照。
2. 每个 agent 使用从该检查点派生的隔离工作区。不能隔离时严格按文件负责人串行交接；不得覆盖、还原或清理他人的变更。分支建议 `codex/memory-a-baseline` 等。
3. 每个任务首先交付小范围实现和验证，不顺带重构无关模块；发现边界外问题先提供定位、证据及接口需求，由集成人派给对应负责人。
4. 不修改真实订阅、不自动停止用户正在使用的代理、不连接示例节点。单元/浏览器测试使用独立数据目录和合成响应；实机网络验收使用明确的测试环境。
5. 不改变节点选择、规则优先级、TUN、DNS 防泄漏、草稿与发布事务语义；保留访问令牌和错误契约。取消请求与丢弃旧响应不是同一件事，分别验证。
6. 数值必须区分实测、模拟、推测和未测；禁止填写推算的“已节省 xx MB”。无性能证据时可交付修复候选，但不得声称达到优化目标。
7. 每个独立分支的文档/代码变更按 `AGENTS.md` 更新 `CHANGELOG.md` 的“未发布”。合并时由集成人整理这些增量，不能覆盖现有历史。共享目录并行时由 agent 提供准确条目，集成人在对应合并补丁中写入。
8. 不擅自发版、部署或覆盖已有发行包。需要验证包时使用独立标签与输出目录，并检查包内源码与当前修改一致。

## 2. 分工、依赖与文件所有权

| Agent | 任务 | 主要写入范围 | 依赖 |
| --- | --- | --- | --- |
| A：测量 | 指标、基线、可复现数据 | `server/resources.py`、`tests/test_resources.py`、`scripts/benchmark-backend.py`；新增 `scripts/measure-memory.ps1`、合成 fixture 和本任务报告 | 最先执行；测量代码稳定后交接 |
| B：前端 | 页面生命周期、连接快照、节点 DOM、编辑副本 | `frontend/src/Client.vue`、`NetworkDashboard.vue`、`ConnectionPanel.vue`、`ProxyPanel.vue`、`ConfigEditor.vue`；新增前端生命周期工具与对应测试 | A 的基线；与 D 冻结可见性事件 |
| C：后端 | 连接缓存释放、配置缓存预算、测速生命周期 | `server/cache.py`、`runtime.py`、`probe.py`、`delay.py`、`api.py`；对应 Python 测试 | A 的基线；涉及 UI 字段先交接口说明 |
| D：原生/托盘 | 托盘轻量入口、隐藏/恢复、可选挂起实验 | `src-tauri/src/desktop.rs`、`main.rs`、必要的 Cargo/能力配置；`frontend/src/main.ts`、`TrayMenu.vue`、新托盘入口、`frontend/vite.config.ts` | A 的基线；B 负责 Client 事件消费 |
| E：验收 | 独立复测、正确性回归、集成结果 | 新增 `scripts/verify-memory-ui.cjs`、独立验收用例及 `docs/memory-validation-2026-10-29.md` | A 给出基线格式；B/C/D 补丁集成后终验 |
| 集成人 | 冻结契约、合并、解决冲突、统一发布记录 | 本方案与指南、汇总 CHANGELOG、必要共享类型/文案、冲突区域 | 各任务检查点 |

测试文件也有所有权：A 维护资源测试；B 新增 `frontend/tests/memory-*.cjs`；C 优先新增 `tests/test_memory_lifecycle.py` / `test_memory_cache.py`，需要改已有测试时列明文件；D 管理原生/托盘测试；E 写独立端到端脚本，不改各 agent 单元测试以“让它通过”。

`frontend/src/api.ts`、`types.ts`、`ResourceMemory.vue`、语言文件和平台契约属于共享接口，按需由集成人指定单一修改人，不能多个 agent 同时改。A 的首轮指标可由外部采样器补齐，不强制修改 UI/API；新增后台接口需要先让 C 接入。

Android/原生 Linux 平台专有代码不在以上默认写入范围；若性能数据指向这些平台，另拆任务。共享前端变化仍需报告两平台兼容性。

## 3. 建议执行顺序

1. **准备检查点。** 集成人锁定源码、输入、Release 工具链和独立测试目录。
2. **A 完成基线。** 明确每个进程的归属、指标含义、主要瓶颈和不确定性；固定验收目标。现有功能失败先记录为 baseline failure，不能冒充新补丁导致。
3. **B/C/D 第一轮并行。** B 做快照释放、DOM 约束和轮询需求；C 做停止缓存清理和有界缓存；D 先测托盘入口增量，再做独立入口。D 不直接启用高风险主窗口销毁。
4. **E 并行准备验收。** 使用 A 的数据和既有行为设计回归，待每个候选补丁到达后独立复测；不要提前复制实现细节写镜像测试。
5. **集成第一轮。** 单项测量通过才合并，处理共享文件和锁序；重测整体结果。收益不足时按测量证据开启编辑副本、连接分页、测速 TTL 或 WebView 挂起下一轮。
6. **完成报告。** 实际通过的项目写明完成；缺设备、权限或稳定数据的项目保持“待验证”，不填假结论。

禁止 B/C/D 同时大量改协议：连接分页、摘要接口、窗口可见性事件先提交字段、错误、超时、失效和兼容性说明，再按生产者 → 消费者顺序集成。

## 4. 可直接派发的任务卡

### Agent A：基线与采样

> 请基于当前源码检查点完成 Clash Studio 内存测量基线。阅读本指南和配套方案，负责 M01。复用 ResourceMonitor 和 benchmark-backend，补齐每进程工作集与 Windows 私有提交量的独立统计，核验 WebView、Python、主/测速内核及权限助手归属。测量 S0–S7；无法执行的场景说明具体缺口。保留旧 API 指标语义，权限不足返回 partial/null。产出三个以上独立运行的数据、环境/输入哈希、进程归属和前三个热点，给出目标冻结建议。不要修改业务轮询、缓存或用户运行配置。

验收要求：

- PID 复用、进程消失、无权限、多个同名应用、主/测速内核同时存在都有覆盖。
- 采样器本身不会不断保存无界内存数组；长采样流式写文件，定期更新进程清单。
- 区分外部进程测量、JS 快照和 tracemalloc 轮次；报告采样开销。
- 对所有输入记录节点数、规则数、组成员总数、连接数与 payload 字节；不能只有“大小配置”。

交付：采样工具、fixture 生成器、原始 CSV/JSON、`docs/memory-baseline-2026-10-29.md`、指标 schema、可复现命令和 SHA-256 清单。

### Agent B：前端驻留数据与 DOM

> 请实施 M02/M03/M04，并根据基线决定是否继续 M07。先修复恢复实时连接后 frozen 未释放的问题；非暂停离页释放大连接数据，但保留筛选、页码、主动暂停快照和单条详情。为代理组提供真正的折叠卸载和大列表渲染预算。盘点顶部实时速率等共享消费者，再建立页面/窗口可见性采样策略和旧响应代次保护。仅对已证明是只读整对象替换的数据使用浅层响应式。不要直接修改 api.ts 协议或原生窗口生命周期；需要 D 的事件时先定义接入约定。

验收要求：

- 暂停 → 恢复后大快照不再被 `frozen` 引用；主动暂停切页回来仍保持暂停语义。用 retained heap 及行为测试证明，不仅搜索源码。
- 30 次进出连接/代理/工作台，DOM/监听器和保留快照数量不持续增长。
- 多组重叠节点、全部展开、搜索/排序、键盘操作、组内/全部测速、连续节点选择正确；逻辑数据不能按可见页截断。
- 后台无 UI 专用周期请求；前台非概览的顶部速率按约定正常显示。回到前台没有多个轮询器，也不展示跨会话旧结果。
- 编辑优化如实施，必须覆盖修改后还原、未保存离开、预览失败、发布中编辑、晚到预览、元信息和网络草稿保护。

交付：分开提交“快照/轮询”“列表渲染”“编辑副本”，对应浏览器行为证据、堆前后对比、请求计数和性能数据；不要一次性改全部页面架构。

### Agent C：后端缓存、连接与测速

> 请实施 M05/M06，按基线推进 M08。梳理所有停止/异常退出/重启/应用失败回滚路径及锁顺序，安全清理旧连接对象、JSON 字节和会话引用。为 RevisionCache 引入可测量预算、超大项不缓存和有界并发构建，保留 single-flight、版本隔离、异常传播和修改隔离。preview 路径会修改返回结果，不允许直接共享可变缓存。测速优化保持四并发、active 引用计数、epoch 取消和配置变化失效。需要分页/摘要接口时先提交兼容契约，未经消费方接入不删除旧字段。

验收要求：

- 停止后旧连接缓存为空，最终累计流量保留；会话替换后旧响应不能回填；不引入锁反转。
- 缓存命中结果被调用方修改时其他调用不受影响；并发同键只构建一次；构建失败所有等待者结束；超预算项仍正确返回；淘汰、不同键压力和等待取消有边界。
- 预算统计明确估算方法，不能用 JSON 长度宣称精准 Python heap；对内存与延迟同时 A/B。
- 测速完成、取消、停止、准备失败和配置切换后，无多余进程/Timer/客户端累积；停止不会被旧请求重新拉起内核。
- 保留应用失败回滚、系统代理恢复和 TUN/DNS 设置；不为释放内存删除回滚必需对象。

交付：生命周期与锁序说明、缓存预算说明、故障注入测试、tracemalloc 热点前后对比、进程数据与接口兼容说明。

### Agent D：托盘与 WebView 生命周期

> 请负责 M09，M10 仅先测量。记录首次打开托盘前后、关闭后、重复开关后的进程/堆增量，优先拆分轻量入口，按实际使用选择必要样式。明确原生隐藏、最小化、恢复、失焦与退出的区别；如浏览器 visibility 状态不可靠，向 B 提供原生可见性事件和初始状态查询。WebView2 挂起作为独立实验，先验证锁定版本接入能力和恢复正确性。不得默认销毁主窗口、丢弃草稿或中断代理；不得移除 IPC 令牌和路径校验。

验收要求：

- 右键托盘首次/重复打开、失焦隐藏、打开主窗、关闭驻留、显式退出均正确；托盘状态仍及时反映内核变化。
- 托盘开关 30 次没有重复窗口和监听器；入口不加载主客户端业务，必要样式仍完整；主窗口启动无退化。
- 挂起若实施，覆盖请求在途、未保存草稿、UAC 提示、后台操作完成、失败恢复、快速连续隐藏/显示。
- Windows 特有 API 有平台边界，Linux 编译和原有托盘菜单行为不受破坏；无法实测的 Linux 行为明确列为待验证。

交付：托盘轻量化补丁与性能对比；可选挂起实验单独补丁、默认策略、能力检测与回退说明。挂起无稳定收益可明确建议不合并。

### Agent E：独立验收

> 请按配套方案对 baseline 和集成候选分别复测 S0–S7，保持机器、输入、Release 配置和进程归属一致。审查是否存在强制 GC、裁剪工作集、改变测试数据或遗漏进程造成的假收益。执行已有回归及新增行为测试，重点验证草稿、节点选择、连接暂停/详情、测速停止、托盘恢复和代理连续性。未测平台、环境故障和基线已有失败单列。不要替实现方改业务代码来通过测试。

验收要求：

- 总进程树、非主内核部分和各角色均提供 before/after；不得排除测速内核隐藏成本，也不得把多个单项收益相加。
- 至少三轮，提供原始数据、统计窗口和命令；峰值与稳定值分开，真实网络与 mock 分开。
- 回归按“通过 / 失败 / 未执行”登记，附证据路径；功能失败优先于内存改善，不能标为可交付。
- 发现持续增长时提供对象保留链或进程/线程增量，不凭一次任务管理器截图判定泄漏。

交付：`docs/memory-validation-2026-10-29.md`、回归矩阵、性能对比、失败复现与最终建议（可合并/需修复/证据不足）。

## 5. 执行命令与验证边界

以下均从 `clashstudio/` 执行，工具路径以 `BUILDING.md` 和当前环境为准；它们是后续执行指南，本次文档交付没有运行这些测试。

```powershell
pnpm --dir frontend check
pnpm --dir frontend test:browser
..\.venv\Scripts\python.exe -B -m pytest tests -q
cargo test --manifest-path src-tauri/Cargo.toml --release
..\.venv\Scripts\python.exe -B scripts/benchmark-backend.py
```

先跑本任务相关测试，再在集成候选跑全量。测试前确认独立数据目录与端口；检查现有浏览器脚本的启动方式。基准脚本默认写 `artifacts/backend-benchmark.json`，前后两次执行应分别归档，避免覆盖 baseline。

新增采样器和验收脚本的命令行参数由 A/E 实现后写入报告，此处不把尚不存在的命令接口当成已可用。Rust 变动需要对应平台编译；共享前端至少构建并做桌面/移动断点回归。Android VPN、Linux TUN、Windows UAC/TUN 等功能需要实际设备/环境验证，不能用构建成功代替。

## 6. 统一交付目录与报告模板

建议将脱敏原始输出保存在 `artifacts/memory/<baseline-id>/<agent-id>/<run-id>/`，报告保存在 `docs/`。大体积 heap dump 和真实网络日志不默认提交到仓库；共享前检查是否包含订阅凭据。交付文件清单附 SHA-256，以便定位报告对应的构建。

每个 agent 使用以下模板，不只交代码截图或一句“已优化”：

```markdown
# 内存优化交付：Agent X

- 状态：完成 / 部分完成 / 阻塞
- 基线标识、父提交、源码快照哈希：
- 对应问题编号、任务范围：
- 改动文件与提交/补丁：
- 触发场景、原行为、新行为：
- 引用/缓存/进程释放条件与并发保护：
- API/事件/配置兼容性；依赖的其他任务：
- 测试命令、退出码、结果和证据路径：
- 未执行项及原因：
- 运行环境、样本、重复次数、统计窗口：

| 场景 | 进程范围 | 指标/单位 | baseline | candidate | 差值/变化率 | 原始数据 |
| --- | --- | --- | --- | --- | --- | --- |
| 待填写实测 | | | | | | |

- 功能/延迟/CPU 回归：
- 风险、剩余问题与回退方式：
- CHANGELOG 增量：
- 结论：达到哪个冻结目标，哪些目标未达到：
```

性能改善计算为 `(baseline - candidate) / baseline × 100%`，同时给绝对 MiB 差值，基线为零则不计算百分比。不得填写未经执行的结果。

最终集成人核对：源码可复现、所有权冲突已解决、指标口径一致、证据完整、无功能阻断、合并后重新测量、CHANGELOG 准确。满足这些条件后再将状态从“方案/候选”改为“已验证优化”。
