# Clash Studio 内存优化方案

日期：2026-10-29。状态：M01–M07 的第一、二批实现、复核 R1–R4 修复、浏览器 DOM/可见性验收和可还原基线已完成；Windows Release 实机 S0–S7、retained heap、M08 测速实验、M09/M10 托盘与桥接、M11 外观 A/B 尚未执行。实施与证据见[实现报告](memory-optimization-implementation-2026-10-29.md)、[复核响应](memory-optimization-review-response-2026-10-29.md)、[浏览器验收](memory-validation-2026-10-29.md)和[基线记录](memory-baseline-2026-10-29.md)。

配套文档：[Agent 任务与交付指南](memory-optimization-agent-guide-2026-10-29.md)。

## 1. 目标与边界

先确定高占用来自界面、Python 服务、主 Mihomo 内核还是独立测速内核，再按证据优化。优先减少无用驻留对象、重复快照和后台工作，保留代理、TUN、DNS 防泄漏、严格分流、编辑保存与失败回滚语义。

第一阶段以 Windows 桌面 Release 包为验收对象；共享前后端必须做 Linux / Android 兼容回归，平台专项内存数据单独记录。未实测平台不得标注性能已达标。Android 的 VPN 生命周期不套用桌面窗口休眠策略。

本方案依据当前工作区源码，而非仅依据已发布的 1.2。工作区有大量未提交和未跟踪变更，实施前必须保存当前源码基线；仅从 HEAD 创建工作树会遗漏本方案审查到的部分代码。

本轮已实施批次 1 与批次 2 的 M01–M07，并保留批次 3 的测量门槛；未调整用户代理、TUN 或运行配置，未宣称整体内存降幅。实现证据见下文所列报告。

## 3. 基线与测量口径

### 3.1 指标

同时采集以下指标，分别报告，避免混为同一个“内存”：

| 指标 | 用途与限制 |
| --- | --- |
| 每进程 Working Set / RSS | 观察物理驻留；含共享页，多进程相加可能重复计算共享内存 |
| 每进程 Private Bytes / 私有提交量 | Windows 主要 A/B 指标；不等于私有工作集，也不等于当前物理 RAM 使用量 |
| JS retained heap、DOM / detached DOM、监听器数 | 定位界面对象与 DOM 的保留；不能代表 WebView / GPU 全部内存 |
| Python tracemalloc current / peak | 定位 Python 分配；不覆盖所有原生库分配，不能当作 Python RSS |
| 请求次数、返回字节、缓存字节估算、并发数 | 证明优化机制与边界，避免只有偶然下降的截图 |
| 启动/恢复耗时、操作延迟 p95、CPU、错误率 | 防止用明显变慢或数据缺失换取低内存 |

Windows 的 `WorkingSetSize` 与 `PrivateUsage` 是不同指标，扩展采样时使用正确结构和权限处理；不可把现有 `total_bytes` 静默改成另一口径。[Microsoft 指标定义](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-process_memory_counters_ex)

建议记录 `timestamp, scenario, phase, pid, process_start_time, role, working_set_bytes, private_bytes, readable, cpu, request_count`。按 PID + 创建时间防止 PID 复用误归属。分组至少包括 Rust 宿主、WebView 进程、Python 服务、主内核、测速内核、权限助手；同一进程只计算一次，无法确认归属时单列，不纳入其他浏览器或应用的 WebView。

权限不足记为 partial / null；不能记零。管理员助手启动的内核不一定在普通父子树内，必须结合受管理 PID 核验；测速内核也应覆盖。分享报告只保留脱敏角色与指标，不包含命令行令牌、订阅 URL、域名连接明细或真实配置。

### 3.2 可复现实验

使用同一机器、Release 构建、相同 WebView2 / Mihomo / 规则库、窗口尺寸、缩放、主题和输入。关闭 DevTools 测总量；堆快照另开诊断轮次。保留完整构建标识、源码快照清单和哈希。

每场景至少三次独立启动。普通场景预热 2 分钟、稳定采样 5 分钟，建议每 2 秒一次。报告各轮稳定窗口中位数、p95、峰值及重复实验范围；短暂分配峰值另用堆分析，2 秒进程采样不能保证捕获瞬时峰值。

| 场景 | 输入和操作 | 关注点 |
| --- | --- | --- |
| S0 空载 | 无订阅、主内核停止，概览前台 | 宿主、WebView、Python 固定成本 |
| S1 普通使用 | 合成 200 节点、3,000 规则；主内核运行 | 常见前台成本与请求频率 |
| S2 大配置 | 合成 2,000 节点、30,000 规则、多个重叠策略组 | 代理 DOM、编辑副本、配置缓存峰值 |
| S3 连接压力 | 500 / 5,000 / 20,000 条可重复连接响应；切页、暂停、恢复、详情 | 全量传输、快照保留与恢复正确性 |
| S4 托盘后台 | 主内核保持运行，隐藏主窗口 10 分钟再恢复；托盘菜单开关 30 次 | 后台采样、额外 WebView、恢复延迟、代理连续性 |
| S5 测速 | 单节点、整组、全部；完成/取消/停止后观察至 180 秒 | 临时内核、Timer、HTTP 客户端释放 |
| S6 编辑/版本压力 | 30 次编辑预览/保存、切换多个订阅，覆盖超过 16 个缓存键 | 深拷贝峰值、缓存预算、保存一致性 |
| S7 稳定性 | 同一流程重复 30 轮并后台运行 60 分钟 | 保留量是否收敛、句柄/线程/进程是否累积 |

合成配置使用假地址且不执行真实代理流量；连接压力默认 mock。模拟结果与真实 Mihomo/系统代理/TUN 结果分别报告，不能以 20,000 条 mock 证明真实网络承载能力。平台联网验证使用独立测试配置，记录实际流量条件。

### 3.3 建议目标，基线后冻结

以下是工程目标，不是已实现或承诺的降幅；Agent A 取得基线后由集成人明确冻结适用场景和数值。

- 第一阶段：在 S2/S3/S6 中至少一个已定位瓶颈场景，客户端非主内核部分的私有提交量稳定中位数或操作峰值下降至少 20%；必须写清选用哪个指标，并同时公布整棵进程树结果。
- S0/S1 稳定中位数不得劣化超过 `max(基线的 5%, 10 MiB)`，正常交互 p95 不劣化超过 10%。测量抖动过大时增加重复次数，不择优挑样本。
- S7 预热后的末 10 分钟中位数相对前 10 分钟增长不超过 `max(10%, 20 MiB)`；另比较 30 轮前后 retained heap 与对象数量。小于门槛不代表证明“没有泄漏”，持续增长仍需解释。
- 隐藏主窗口后，UI 专用连接/曲线/内存定时请求归零；允许在途请求结束及必要的后台生命周期/托盘同步。恢复后建议 2 秒内获得新状态，超时明确显示陈旧数据，不继续冒充实时数据。
- 所有暂停快照、连接缓存、测速任务和临时内核都有明确释放条件；小列表不增加分页负担；不降低代理正确性或编辑可靠性。

## 4. 分批实施方案

### 批次 0：测量与基线（P0，必须先完成）

扩展现有采样和 `scripts/benchmark-backend.py`，分别保留端到端进程数据、Python 分配数据和前端堆证据。原脚本已有合成配置及 5,000 连接基准，可复用输入构造；不能用它内部的模拟 before/after 取代本轮两个真实构建版本的 A/B。

输出进程归属图、前三个内存来源、可复现路径、数据文件、指标口径。若主内核占大头，应先缩小 UI 优化的预期，不能把核心规则库常驻量算作 Vue 泄漏。

### 批次 1：清理过期数据与约束列表（P1）

1. **连接快照生命周期。** 恢复实时显示立即释放 `frozen`；保留用户主动暂停的快照及筛选语义，离页不静默取消暂停。非暂停离页可释放大列表，保留筛选/页码/单条详情；回页先刷新再展示。增加采样代次，防止晚到响应把已清掉的数据重新写回。禁止直接用 `v-if` 卸载整个组件而丢掉已有暂停/详情状态。
2. **后端清理。** 在停止、会话替换和异常退出路径清除旧连接对象、编码字节及会话引用；最终流量只留下累计数。梳理 `sample_lock/lifecycle_lock/runtime.lock` 顺序，不能在相反锁序下增加清理；回滚需要的 `last_composed/active_row` 另行定义生命周期，不能随意删除。
3. **列表按需创建。** 折叠的代理组不保留节点 DOM；展开的大组优先采用与现有 UI 一致的分页，必要时再虚拟化。建议单组每页最多 100 项，并设计跨多个展开组的全局渲染预算，防止每组 100 项但总数仍数千。搜索、排序和“全部测速”基于完整逻辑集合，不局限于可见页。
4. **轮询明确需求。** 区分当前页面、窗口可见性、共享顶部速率消费者和内核状态。首页图表不需要时停更新；若其他页面仍显示速率，保留共享轻量采样而非无条件停掉。主窗口后台停止 UI 专用采样，原生托盘继续必要同步。沿用 single-flight，恢复只触发一次新采样；切页后旧响应不得覆盖新状态。
5. **只读大对象。** 对整对象替换的连接列表/目录快照考虑 `shallowRef`，先核查嵌套修改调用点。编辑草稿继续响应式，节点选择的乐观更新需改成明确替换或保留正确通知机制。Vue 官方建议大列表限制渲染量，并对大型不可变数据考虑浅层响应式；这不是把所有 `ref` 替换为 `shallowRef` 的依据。[Vue 性能指南](https://vuejs.org/guide/best-practices/performance)

### 批次 2：减少配置副本与重复载荷（按基线选择 P1/P2）

- **缓存预算。** 保留现有同键请求合并、异常传播和版本键；增加条数与估算字节双上限。初始实验值可用 8 项 / 32 MiB，但必须以实测校准；序列化长度只是估算，不等于 Python 对象真实占用。单项超预算仍正常返回，选择不缓存。记录命中、淘汰、估算字节、在建项数，限制不同键同时构建的数量及等待队列。
- **复制边界。** 先用 tracemalloc 找出副本代价，再选择在所有权边界复制、只缓存不可变表示或只缓存必要字段。当前 `/api/client/preview/{id}` 会 `result.update(...)`，直接返回共享可变缓存会串改数据；禁止为了少复制移除隔离而不审计所有调用者。
- **编辑状态。** 分离不可变源配置、可变 edits 和最近成功预览。只保留保存/冲突处理必需的快照。改造 dirty 判断要保持“修改后撤销回原值则不脏”、元信息、网络草稿、发布快照与晚到草稿语义。预览做到单个在途请求加最新待处理版本，代次丢弃和取消分别设计。
- **摘要和完整数据分开。** 按消费者列出字段，概览不默认取整份 YAML/完整节点详情；工作台、导出和应用校验按需取全量。接口采用可选字段或新增摘要路径，旧契约先保持。不能只让前端丢弃服务端已经生成并传输的大字段。
- **连接传输。** 后端分页只在全量传输已被实测为瓶颈时引入；约定全局筛选/排序、总数、采样时间、会话及 snapshot_id，保证分页期间快照一致。前端已有分页只限制 DOM，不减少全量响应。流量摘要现在仍依赖 `/connections`；替换为其他 Mihomo 接口前需核对仓库随附版本的能力及连接计数/累计流量语义。
- **桥接层。** 先减小响应字段和重复请求，再评估 Rust JSON 中转。保留本机令牌、路径校验和结构化错误，不为减少拷贝绕过认证。

### 批次 3：测速、托盘与外观驻留（P2/P3，证据决定）

- 测速内核现有 120 秒 TTL 已有复用价值。A/B 比较 30 / 60 / 120 秒，明确测完到回收耗时、连续测速启动开销和失败率；保持活跃引用计数和停止 epoch。Timer 可改成单个可重置截止时间，但不要因线程“看起来多”直接重写。
- 测速目录按配置版本和会话复用，避免每个节点读取全量 `/proxies`；动态 Provider 刷新、节点消失与会话变更必须失效，仍遵守四并发上限。
- 托盘先拆轻量入口，仅加载托盘所需组件/样式；比较菜单打开前后和隐藏后的进程/堆增量。之后才比较隐藏保留、空闲后销毁重建、适用平台原生菜单三个方案；不得破坏现有菜单行为和 Linux 托盘兼容。
- Windows 隐藏主窗口可做 WebView2 挂起实验，先验证当前 Tauri/wry 版本可用接入点、UI 线程要求、挂起失败和恢复行为。Microsoft 提供后台内存管理建议，但不保证当前封装有对应 API。[WebView2 性能指南](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/performance)
- 主窗口销毁重建风险高于挂起，放在最后评估；不得丢未保存草稿、绕过关闭确认、停止主代理或失去后台操作通知。
- 外观优化先比较无照片/有照片、玻璃效果开/关，再处理可归因的重复合成层。保留默认设计和用户选择；已有图片处理上限不要重复宣称新增。

不作为首轮方案：整体移除 Python 或重写框架、强制关闭硬件加速、删用户规则、降低 DNS 防护、强制触发 GC、定期重启进程、调用 EmptyWorkingSet 粉饰卡片数字。若后续提出架构迁移，应独立评估迁移成本和兼容性。

## 5. 验收与回退

每个补丁应对应上表编号、一个可复现行为测试和同条件性能对比。正确性至少覆盖：节点选择、草稿预览/保存/撤销、发布冲突、切订阅、连接筛选/暂停/详情、测速取消/停止、托盘恢复、停止恢复系统代理、TUN 与 DNS 防泄漏设置保持。

前端行为测试在真实组件或浏览器中观察请求、DOM 和状态；源码字符串断言不能证明资源被释放。后端用故障注入覆盖晚到响应、会话替换、缓存构建异常和回滚；实机代理恢复必须单独记录，mock 不能代替。

每批独立补丁/提交，先单项 A/B，再集成 A/B；不能把各项百分比相加。预算、TTL、休眠等策略集中配置并记录默认值，保证可单独回退。出现草稿丢失、错误节点/规则、代理停止、无法恢复窗口或明显性能倒退时阻断合并。

最终交付结构及执行顺序见 [Agent 任务与交付指南](memory-optimization-agent-guide-2026-10-29.md)。
